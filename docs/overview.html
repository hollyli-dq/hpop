HPOP.  Hierarchical Partial-Order Skill Programs

Raw agent traces → reusable skill programs as partial orders → fast DAG inference  ·  project overview  ·  updated Jun 2026

Thesis

The recovered partial order is the product — a precompiled "recipe". At inference time we don't re-derive a plan with an LLM; we traverse a DAG (parallel where incomparable, search-pruned to linear extensions, reusable, cheap legality checks). The model is grounded in BPOP (Bayesian latent partial orders, frontier-softmax) and extended to a hierarchical skill-library model; the data side is the PDAF annotation framework that turns WebLINX traces into typed, confidence-weighted priors.

The model — hierarchical Bayesian skill library

A Dirichlet-process mixture over partial orders

  • Skill = a local partial order P_r, BPOP-parameterized by latent U^(r)∈ℝ^(m×K) — poset = intersection of K realizers (a≻b ⇔ U_a>U_b ∀k); K inferred by RJMCMC.
  • Library {P_r} ~ DP(α, G₀) — reusable atoms shared across the corpus.
  • Global PO Q over skill instances (recurring types = R).
  • Both levels scored by the tractable robust frontier-softmax (O(T·|A|); avoids #P-hard linear-extension counting).

New-skill penalty (the key term)

log p(z₁:ₙ | α) = K·log α + Σ_r log Γ(n_r) + log Γ(α)/Γ(N+α)
Ewens EPPF: each new skill costs −log α; reusing a size-n_r skill costs only log n_r; a new skill also pays a Bayesian-Occam marginal. One knob α controls reuse↔novelty (Pitman–Yor for power-law libraries). Full spec: docs/model_formal.tex (→ pdf), readable: docs/MODEL.md.

End-to-end

WebLINX trace
  → ingest        raw events  (weblinx.py)
  → normalize     action tokens                                  [Step 1a]      data/interim/
  → annotate      LLM: CPAs → skill instances → typed edges      [Steps 1b–3b] data/annotated/
  → extract       orders.jsonl → local poset priors H_r + global poset prior Q
  → infer (HPOP)  DP-mixture over partial orders; frontier-softmax both levels;
                  CRP new-skill penalty (−log α);  MCMC / semi-Markov
  → compile       frontier executor  →  parallel where ∥, reuse skills, no re-planning
PDAF is the offline prior generator; HPOP/BPOP is the inference engine. skill_is_new from the annotator = the empirical CRP "new-table" event.
